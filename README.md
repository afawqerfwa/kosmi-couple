# Kosmi Couple for Cloudflare

اتاق دونفره‌ی تماشای مشترک با ظاهر بنفش، چت، سینک کامل کنترل‌ها و پخش زنده‌ی فایل محلی از مرورگر یک نفر به نفر دوم.

## امکانات

- اتاق خصوصی با ظرفیت دقیقاً دو نفر و لینک قابل کپی
- همگام‌سازی پخش، توقف، جلو/عقب بردن، سرعت، صدا و mute
- دکمه‌های مشترک پخش/توقف، ۱۰ ثانیه عقب، ۱۰ ثانیه جلو و نوار زمان
- پخش زنده‌ی فایل محلی با WebRTC؛ فایل کامل روی سرور یا حافظه‌ی نفر دوم ذخیره نمی‌شود
- چت داخل اتاق و نمایش وضعیت اتصال
- Durable Object جداگانه برای هر اتاق
- استاتیک سایت با Cloudflare Assets
- پشتیبانی از STUN و تنظیم TURN برای شبکه‌های سخت‌گیر

## انتشار روی Cloudflare Workers

این پروژه برای **Cloudflare Workers + Durable Objects** آماده است، نه Railway و نه Node/Express.

1. در Cloudflare یک API Token یا ورود Wrangler را آماده کنید.
2. داخل پوشه‌ی پروژه اجرا کنید:

```bash
npm install
npx wrangler login
npx wrangler deploy
```

3. Wrangler یک دامنه‌ی `workers.dev` می‌دهد. همان لینک را برای نفر دوم بفرستید.

فایل `wrangler.toml`، سرویس استاتیک، Worker و Durable Object اتاق‌ها را تنظیم می‌کند. برای GitHub Actions یا Deploy خودکار Cloudflare، دستور Deploy همین است:

```bash
npx wrangler deploy
```

## اجرای محلی Cloudflare

```bash
cp .dev.vars.example .dev.vars
npm install
npx wrangler dev
```

سپس آدرس محلی‌ای که Wrangler نشان می‌دهد را باز کنید. برای تست واقعی، دو پنجره یا دو دستگاه را با یک کد اتاق وارد کنید.

## تنظیم TURN

اعتبارنامه‌های تصویر ارسالی عمداً داخل GitHub یا ZIP قرار نگرفته‌اند. آن‌ها را در Cloudflare Dashboard از مسیر **Workers & Pages → پروژه → Settings → Variables and Secrets** به‌صورت Secret اضافه کنید:

```text
TURN_URLS=turn:HOST:3478,turns:HOST:5349
TURN_USERNAME=نام کاربری TURN
TURN_PASSWORD=رمز TURN
```

یا آرایه‌ی آماده‌ی ICE را در یک Secret با نام `TURN_ICE_SERVERS_JSON` قرار دهید:

```text
[{"urls":["turn:HOST:3478"],"username":"...","credential":"..."}]
```

آدرس واقعی `HOST` را از **Show ICE Servers Array** در سرویس TURN بردارید. رمزها را داخل GitHub یا فایل‌های پروژه commit نکنید.

می‌تونید به‌جای Dashboard، از خط فرمان هم Secret ست کنید (مثلاً برای metered.ca):

```bash
npx wrangler secret put TURN_URLS
# مقدار: turn:global.relay.metered.ca:80,turn:global.relay.metered.ca:80?transport=tcp,turn:global.relay.metered.ca:443,turns:global.relay.metered.ca:443?transport=tcp

npx wrangler secret put TURN_USERNAME
npx wrangler secret put TURN_PASSWORD
```

⚠️ اگه usernam/credential حساب metered.ca خودتون رو جایی (چت، issue گیت‌هاب، و غیره) paste کرده‌اید، حتماً از پنل metered.ca عوضش کنید (rotate). هر کسی که اون مقادیر رو ببینه می‌تونه از پهنای باند TURN شما مصرف کنه.

بدون تنظیم TURN، پروژه فقط با STUN (`stun.l.google.com`) کار می‌کنه که برای اکثر شبکه‌های خانگی کافیه ولی برای شبکه‌های سخت‌گیر (موبایل بعضی اپراتورها، VPN، NAT متقارن) پخش مستقیم فایل ممکنه وصل نشه.

## نکات پخش

- فایل محلی به‌صورت زنده از مرورگر نفر اول به نفر دوم می‌رود؛ هر دو نفر باید صفحه را باز نگه دارند.
- حجم فایل به‌تنهایی معیار مصرف نیست؛ کیفیت و bitrate فیلم و مدت تماشا تعیین‌کننده‌اند.
- اگر پخش سمت دوستتان خودکار شروع نشد، روی دکمه‌ی «▶ پخش» بزنید.
- لینک فیلم باید مستقیم و قابل پخش در مرورگر باشد؛ بعضی سایت‌ها CORS یا محافظت ضدجاسازی دارند.
- برای شبکه‌های سخت‌گیر، TURN را حتماً تنظیم کنید. STUN به‌تنهایی همیشه کافی نیست.
- اطلاعات اتاق و چت در Durable Object ذخیره‌ی موقت می‌شود؛ فایل ویدئو روی Worker ذخیره نمی‌شود.

## رفع اشکال سینک‌نشدن (این نسخه چی رو درست کرد)

باگ اصلی این بود: هر بار مرورگر به‌خاطر رفرش، قطعی موقت شبکه یا خوابیدن Durable Object دوباره وصل می‌شد، سمت سرور یه **هویت تصادفی جدید** بهش می‌داد. این باعث می‌شد اون آدم به‌عنوان «نفر سوم» رد بشه یا جای قدیمیش توی اتاق به‌صورت duplicate/ghost بمونه، و در نتیجه چت، تغییر فیلم و کنترل پخش دیگه به دستش نمی‌رسید — بدون اینکه هیچ خطای واضحی نشون داده بشه. همچنین سمت کلاینت اصلاً منطق **اتصال مجدد خودکار** وجود نداشت، پس اگه سوکت یه بار قطع می‌شد، برای همیشه ساکت می‌موند تا کسی صفحه رو رفرش کنه.

تغییرات این نسخه:

- **هویت پایدار برای هر نفر:** هر مرورگر یه `clientId` توی `localStorage` می‌سازه و همیشه همون رو می‌فرسته؛ سرور دیگه رفرش/قطعی رو «نفر جدید» حساب نمی‌کنه و جای قبلی‌شو دقیق نگه می‌داره.
- **اتصال مجدد خودکار با backoff:** اگه WebSocket قطع بشه، کلاینت خودش با فاصله‌ی زمانی افزایشی دوباره وصل می‌شه و بی‌صدا `room:join` می‌زنه تا وضعیت اتاق (فیلم، چت، پخش) رو از سر بگیره.
- **Heartbeat/ping-pong:** هر ۱۵ ثانیه یه ping می‌ره؛ اگه ۳۵ ثانیه جواب نیومد، سوکت به‌عنوان مرده در نظر گرفته می‌شه و اتصال مجدد شروع می‌شه (بعضی وقت‌ها مرورگر onclose رو دیر صدا می‌زنه).
- **جلوگیری از duplicate seat:** اگه یه clientId دو تا سوکت زنده داشته باشه (مثلاً حین رفرش)، سرور سوکت قدیمی رو می‌بنده تا جای واقعی نفر دوم اشغال نمونه.
- **سینک بهتر پخش زنده:** وقتی استریم WebRTC تازه وصل می‌شه، بلافاصله با آخرین وضعیت پخش (زمان/سرعت/pause) هم‌راستا می‌شه، نه از ثانیه‌ی صفر.
